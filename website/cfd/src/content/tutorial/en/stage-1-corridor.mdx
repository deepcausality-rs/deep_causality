## Before you start

Run it. It took 44.4 s on {MACHINE}.

```bash
cargo run --release -p avionics_examples --example plasma_blackout_corridor
```

The run ends with thirteen gate lines. A *gate* is a pass or fail check on a
result. The last line reads:

```text
[PASS] [tripwire] (5b) wall-clock budget: 44.4 s elapsed (budget 600 s)
```

`[tripwire]` means the limit comes from this program's own earlier output, so a
pass shows no regression. The flow layer is a 32×32 grid. Excerpts drop lines that
do not bear on the point.

## Station 1: One closure, one exit path

One closure returns a single `Result`, so every failure leaves by the same path.
Open `corridor/main.rs` at `fn main`.

```rust
let outcome: Result<Verdict, StudyError> = (|| {
    // ... every leg and the campaign live in here ...
})();

match outcome {
    Ok(verdict) => {
        println!("\n{verdict}");
        if verdict.passed() { ExitCode::SUCCESS } else { ExitCode::from(1) }
    }
    Err(e) => {
        eprintln!("plasma-blackout corridor failed: {e}");
        ExitCode::from(2)
    }
}
```

The library neither prints nor exits. `verdict()` returns data, and the caller
decides what it means. Exit code 0 means every gate passed, 1 a gate failed, 2 the
run never reached judgement, so CI can tell a physics change from a broken build.

## Station 2: The run finds where blackout starts

No constant in the program says where blackout starts. The run finds it, 131 steps
in at 73.2 km.

```rust
let onset = CfdFlow::march(&nominal)
    .couple(world::corridor_coupling(1.0, 0))
    .trigger(utils::trigger())
    .kappa(lift(0.0))
    .from_field(world::initial_field())
    .until(|field, _| field.regime().map(|r| r.gnss_denied).unwrap_or(false))
    .map_err(leg_err("leg: descent to blackout onset"))?;
```

The `.until` condition asks the field for its regime. The regime carries a
`gnss_denied` flag (GNSS is satellite navigation such as GPS), which the classifier
sets from the electron density the chemistry stage evolved on the previous step.

A fixed `.run_for(131)` reproduces today's numbers and fails on the next
atmosphere. [Walk 2](/tutorial/stage-2-weather/) flies six atmospheres, and blackout
starts between 12.1 s and 14.6 s. Only the standard day starts at step 131, so the
other five would fly the wrong window, and no gate would notice, because its
reference value would be the hardcoded one.

Rule 1: **a boundary between legs, the stretches of descent between pauses, is an
event the run locates, not a station it is told to switch at.**

## Station 3: The stages run in physics order

A *coupling* is an ordered list of stages that run after every solver step over one
shared state. This is `corridor_coupling` in `src/shared/world.rs`, reduced to its
shape:

```rust
Coupling::between_steps()
    .then(VibrationalLagStage::new(/* Millikan-White bath */)
        .with_pressure_field("pressure_atm"))
    .then(FiniteRateIonizationStage::new(n_tot)
        .with_density_field("n_tot")
        .with_sheath_renewal(sheath_peak_age))
    .then(RegimeClassify::new(l_char, trigger))
    .then(BankSteeredLift::new(rho_ref, cda_over_m, l_over_d))
    .then(TrajectoryNav::new(q_diag, gnss_var, optical_var).with_imu(imu))
    .then(CyberneticCorrect::new(SafetyEnvelope::new(q_max, g_max, bank_max)))
    .build()
```

The order follows the physics. Vibrational relaxation sets the temperature, the
chemistry writes the electron density, the classifier reads it to decide whether the
GNSS link exists, and navigation folds in only the fixes the classifier permits.

Stages communicate through named fields on the shared state. The classifier reads
`"n_e"` and holds no reference to the chemistry stage, so a stage can be inserted,
removed or reordered without touching its neighbours. Walk 3 adds thrust and plume
stages to this stack and leaves them inert. The stack is a nested generic type, so
the compiler resolves every stage call at build time.

## Station 4: One fork gives every bank angle the same past

Six separate descents would each carry their own history. The fork starts every
candidate from one shared state.

```rust
let corridor = CfdFlow::study("bank-angle corridor")
    .cases(model::coarse_commands())
    .fork(&onset)
    .branch(model::bank_world)
    .continue_for(constants::BRANCH_STEPS)
    .reduce_all(model::score_branches)
    .inspect(|rows| utils_print::print_branches(COARSE_TITLE, rows))
    .refine(&onset, model::fine_candidates)
    .branch(model::bank_world)
    .continue_for(constants::BRANCH_STEPS)
    .reduce_all(model::score_branches)
    .record(table_path())
    .gates(model::corridor_gates())
    .verdict()?;
```

`bank_world` builds each branch's *world*: the run's description with one declared
difference, here the bank angle.

At the pause the vehicle holds one degraded navigation state: a Kalman filter at a
particular covariance, an accumulated drift, and a plasma sheath at a particular
electron density. The question is which command is best from that state, and
separate descents would each build their own. Branches also share the paused state
until one writes to it, so forking costs less.

`.refine` forks the same pause, not the first round's winner, so both rounds score
against one aim point. `reduce_all` sees the whole set because the aim point
derives from the zero-bank (ballistic) branch.

The coarse table, from the `miss (traj)` column of your output:

```text
 0.0 deg  20.000 m
 5.0 deg  11.581 m
10.0 deg   3.533 m
15.0 deg   6.002 m
20.0 deg  14.303 m
40.0 deg  28.881 m
```

The 20.000 m at zero bank is set by construction. The example places the aim point
`AIM_CROSS_RANGE_M = 20.0` m to the side of the unsteered landing point
(`constants.rs`). The other five rows are measurements. The miss falls, then rises,
and at 40 degrees it exceeds the unsteered case.

## Station 5: Every tuned number carries its reason

```rust
pub const BANK_ANGLES_DEG: [f64; 6] = [0.0, 5.0, 10.0, 15.0, 20.0, 40.0];
```

The comment in `constants.rs` says 40 degrees "exceeds the envelope cap, flies
clamped, and overshoots", and the 28.881 m in your output is what that costs. The
`AIM_CROSS_RANGE_M` comment says the aim is sized so the best bank falls inside the
cap and between two candidates, so the sweep has to find it.

The sweep stops at 0.5 degrees and 2.07 m. Finer steps would optimize below what
the vehicle can know: its navigation error in this run is 1.67 m when the branches
are scored, and it keeps growing to 42.4 m before GPS returns
(`corridor_trace.csv`). A flight system commands off the navigated state, so finer
steering returns nothing.

## Station 6: Every band is a const

Thirteen gates judge the run, and the process exits nonzero if any fails. An
assertion would stop at the first failure. The gate sequence evaluates all thirteen
and merges one verdict. A gate is a plain `fn` pointer that captures nothing. The
retropulsion example's `constants.rs` states the consequence:

```text
Every gated band is a `const` here because a gate is a plain `fn` pointer that
captures nothing: a band held anywhere else cannot be reached from the gate
that enforces it.
```

So every threshold is a documented `const` beside the code that uses it.

## Try it yourself

Each change takes about 45 s to run, plus a rebuild.

**1. Move the target.** Set `AIM_CROSS_RANGE_M` to `10.0`. The best bank angle
should fall. Check whether gate 4e, which requires the best branch to beat zero
bank by 3 times, still passes.

**2. Reproduce station 2's failure.** Replace the `.until` condition with
`|_, step| step >= 131`. Everything should still pass. Then, in
`corridor/model.rs`, swap `world::standard_atmosphere()` for
`world::weather_atmosphere(-40.0, 1.2)`. The condition version should pause near
step 124 (12.4 s, walk 2's polar_winter row), and the fixed version at step 131.

## What this walk established

Four rules that walks 2 and 3 reuse:

1. A leg boundary is an event the run locates.
2. Stages communicate through named fields on one shared state.
3. A what-if forks a paused state, so every branch carries the same past.
4. The library returns data, gates read consts, and the caller owns the exit code.
