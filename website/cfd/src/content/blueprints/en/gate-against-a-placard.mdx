A placard is a posted operating limit, such as a maximum dynamic pressure. The flight envelope
placard example checks sixteen Mach-altitude points against two limits and prints:

```text
[PASS] q-max placard: max q = 23.7 kPa at M 1.20 / 11.0 km, inside the 60 kPa placard
[PASS] stagnation temperature: max T0 = 1502.1 K at M 5.00 / 40.0 km, inside the 1700 K placard
=== All gates passed: flight envelope placard. ===
```

Give it a matrix with one point past the limit and it prints the offender, then exits 1. The
closing line reads `=== Gate REGRESSION in flight envelope placard: see the FAIL lines. ===`.

```text
[FAIL] q-max placard: q = 85.1 kPa at M 1.50 / 5.0 km exceeds the 60 kPa placard
```

Two pieces of code produce this. The first names the gates. From
`examples/avionics_examples/cfd/flight_envelope_placard/model.rs`:

```rust
pub fn placard_gates() -> GateSeq<PlacardRow> {
    GateSeq::new("flight envelope placard")
        .gate("q-max placard", gate_q_max)
        .gate("stagnation temperature", gate_stagnation_temperature)
}
```

Each gate is a function from the study's rows to a pass flag and a message. Condensed from
`gate_q_max`:

```rust
pub fn gate_q_max(view: &StudyView<'_, PlacardRow>) -> (bool, String) {
    // q_max is the placard limit lifted into FloatType; peak is the row with the highest q.
    let offenders: Vec<String> = view.rows().iter()
        .filter(|r| r.q_kpa > q_max)
        .map(|r| format!("q = {:.1} kPa at M {:.2} / {:.1} km", r.q_kpa, r.mach, r.alt_km))
        .collect();
    if offenders.is_empty() {
        (true, format!("max q = {:.1} kPa at M {:.2} / {:.1} km, inside the {Q_MAX_PLACARD_KPA:.0} kPa placard",
                       peak.q_kpa, peak.mach, peak.alt_km))
    } else {
        (false, format!("{} exceeds the {Q_MAX_PLACARD_KPA:.0} kPa placard", offenders.join("; ")))
    }
}
```

The second maps the verdict to an exit code. From `main.rs`:

```rust
match placard_study() {
    Ok(verdict) => {
        print!("{verdict}");
        if verdict.passed() { ExitCode::SUCCESS } else { ExitCode::from(1) }
    }
    Err(e) => {
        eprintln!("flight envelope placard setup failed: {e}");
        ExitCode::from(2)
    }
}
```

## The library reports and your program decides

`verdict()` resolves the study to a `Verdict`. It does not print and does not exit. Mapping it to
an exit code is your program's job, so one study serves as a CI check in one binary and as a
report in another. The examples use 0 for all gates passed, 1 for a failed gate and 2 for a
setup failure. Every verification target and every gated example exits nonzero when a gate
fails.

## A gate is a tripwire or a reference

`.gate` adds a tripwire: its bound is pinned from this code's own earlier output, so a pass
shows the result has not regressed. `.reference_gate` adds a reference: its bound is an
analytic solution or a published value, and the citation belongs where the bound is defined.
The verdict prints the class after PASS or FAIL, as in the corridor's `[PASS] [tripwire] ...` lines.
The committed placard output predates the class tag.

## Write the number into the message

The placard messages carry the measured value and the limit. A bare `[PASS]` records only the
outcome. A message with both records the margin: a pass at 58 kPa against a 60 kPa placard and a
pass at 24 kPa carry different information.

## Gate the validated band

The [VIV example](/examples/viv-resonance-margin/) checks its Strouhal number against
`[0.16, 0.21]`, a band pinned from a measured run on its own grid and domain. Grid resolution
and 16.7 percent blockage push the Strouhal number above the unconfined value of about 0.164.
The example pins the band from its own measurement and gates regressions against it.

## A passing gate is not a passing physics target

The momentum-jet study for supersonic retropropulsion ends with `GATES PASSED`, directly under a
recorded miss against the Jarvinen–Adams drag reference. The gate protects a negative finding
from regressing. Its claim is that the measured structure is reproducible.

Read what each gate asserts before you treat a green run as validation. See the
[limits page](/boundaries/#srp).

## Gate for the failure you can detect

A wake march that decays to a steady state produces a finite signal, and a frequency extractor
reports noise as a frequency. The VIV example gates on a finite, oscillating wake rather than
on finiteness alone. The [cylinder verification](/validation/#dec-cylinder) records the failure:
with a staircase wall the wake decays, and the detector reports `St ≈ 0.244` from
seventh-decimal noise.
