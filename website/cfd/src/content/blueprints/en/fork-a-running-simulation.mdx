The corridor example pauses a reentry descent when the plasma blocks the GPS signal. It then
flies six bank angles from that one pause and prints how far each lands from the aim point.

| Bank angle | Miss from the aim point |
|---|---|
| 0.0° | 30.000 m |
| 5.0° | 16.463 m |
| 10.0° | 3.818 m (closest) |
| 15.0° | 11.516 m |
| 20.0° | 24.988 m |
| 40.0° | 48.426 m |

The setup fixes the first row. The aim point sits 30 m to the side of where the unsteered
branch lands (`AIM_CROSS_RANGE_M = 30.0` in the example's `constants.rs`), so a zero-bank miss
of 30.000 m is a property of the setup and not a measurement. The study measures which bank
angle gets closest. A second round of eleven finer branches, forked from the same pause, lands
at 11.0° and 2.87 m.

Two calls produce this. The march pauses when a condition on the evolved flow becomes true. The
study forks that pause. Condensed from
`examples/avionics_examples/cfd/plasma_blackout/corridor/main.rs`, with the `.kappa`, `.inspect`
and error-mapping calls left out:

```rust
// March until the plasma blocks the GPS signal, then pause.
let onset = CfdFlow::march(&nominal)
    .couple(world::corridor_coupling(1.0, 0))
    .trigger(utils::trigger())
    .from_field(world::initial_field())
    .until(|field, _| field.regime().map(|r| r.gnss_denied).unwrap_or(false))?;

// Fork the pause: one branch per bank command, then refine from the same pause.
let corridor = CfdFlow::study("bank-angle corridor")
    .cases(model::coarse_commands())
    .fork(&onset)
    .branch(model::bank_world)
    .continue_for(constants::BRANCH_STEPS)
    .reduce_all(model::score_branches)      // aim point from the ballistic branch first
    .refine(&onset, model::fine_candidates) // 0.5-degree bracket around the coarse winner
    .branch(model::bank_world)
    .continue_for(constants::BRANCH_STEPS)
    .reduce_all(model::score_branches)      // same aim point: the rounds stay comparable
    .record(table_path())
    .gates(model::corridor_gates())
    .verdict()?;
```

The condition reads the evolved field, so the pause lands where the chemistry crossed the
receiver cutoff. See [detect and act on a regime change](/blueprints/handle-regime-change/).
`refine` forks the same `onset` pause a second time. Both rounds call
`reduce_all(model::score_branches)`, so they score against one shared aim point.

## A branch differs in one published constant

Each branch builds its own world: the description of the run with one declared difference. Here
the difference is the commanded bank angle. From `model.rs`:

```rust
pub fn bank_world(cmd: &BankCommand) -> Result<CompressibleMarchConfig<FloatType>, PhysicsError> {
    descent_world(cmd.name, cmd.deg)
}
```

`descent_world` passes `&[("commanded_bank", utils::rad(bank_deg))]` to the shared world
builder, which publishes each constant with `publish_constant`. The `CommandedBank` stage reads
that constant into the control channel every step, and `CyberneticCorrect` clamps it against
the envelope.

## The event log records which world a branch replaced

Every branch continues from the pause in its own world and adds a `!!ContextAlternation!!` entry
to its event log, naming the world it replaced. The corridor gate reports it:

```text
[PASS] [tripwire] (4c) counterfactual steering: 17 alternated worlds (6 coarse + 11 fine) from one shared onset; coarse-winner-vs-ballistic terminal separation 27.10 m; coarse miss spread [3.82, 48.43] m
```

The retropropulsion example gates it per branch: 5 of 5 branches record an applied world change
naming the world they replace. After the study, the corridor's diagnostic legs call
`alternate_context` directly to fly the committed branch's world.

## A fork costs little until a branch writes

The fork shares the marched flow state, and a gate confirms that no tensor is copied at fork
time. Each branch copies the coupled field (the per-cell scalars, the navigation filter and the
event log) at its first write, so the per-branch cost grows with the cell count.

Continuing a branch costs about the same as an unforked march. In the plume-coupled study
(`studies/qtt_rank_plume`), three recordings span 0.95 to 1.05 times the unforked step cost on
the powered branches, and a coasting branch costs 0.66 times as much because it does less work.
Read those as indistinguishable from an unforked march, not as three-digit figures. The study
also prints a fork setup time. It is one sub-microsecond measurement that moved from 42 ns to
83 ns between recordings, so do not plan against it.

`fork` itself does not fail. A broken pause passes through, and each branch reports the pause's
error at `continue_for`, so the failure stays attributable.

## A state fork differs from a parameter fork

A parameter fork reruns a model from different inputs, and each branch is an independent run.
The [weather table](/tutorial/stage-2-weather/) has that shape.

A state fork pauses one marched, coupled field and continues every branch from it, so each
intervention feeds back into the flow it inherited. The corridor has that shape.

For a state fork, compare each branch against a frozen-field prediction of the same
intervention: the same command schedule with the flow closure held at its value at the fork. If
simple kinematics reproduces the divergence, the flow did not contribute to it.

The [retropropulsion descent](/tutorial/stage-3-retropropulsion/) runs that comparison as gate 4c. Its
branches depart the frozen-drag prediction by up to 179.9 m/s against a 100 m/s threshold. Its
flow observables spread 0.0844 across the branches, where the corridor's bank branches agreed
to three digits.
