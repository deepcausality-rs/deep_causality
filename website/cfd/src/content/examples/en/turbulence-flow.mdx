## What the run printed

This example forecasts the Lorenz system, a three-mode truncation of convection, at
three precisions. It runs no CFD solver. An f32 forecast stays within one
state-space unit of the reference until t ≈ 21.5, and an f64 forecast until
t ≈ 44.5. Float106 is still inside at T = 60, where the run ends. The law below puts
its horizon near 81.

```text
Forecast horizon (lead time before the flow state is off by one state-space unit):
  f32        t ≈ 21.5
  f64        t ≈ 44.5
  Float106   beyond T=60 here; the law below puts it near t ≈ 81
```

The reference is the Float106 run. All three precisions use the same scheme, `Rk4`
at `dt = 0.005`, so truncation cancels and the distance to the reference is roundoff
growth alone.

```text
     t    |  f32 vs F106  |  f64 vs F106
  --------+---------------+--------------
     5.0  |     2.69e-5   |    2.31e-14
    10.0  |     1.48e-4   |    1.09e-13
    15.0  |     4.49e-3   |    4.62e-12
    20.0  |     1.94e-1   |    1.96e-10
    25.0  |      1.99e1   |     4.01e-8
    30.0  |      1.75e1   |     2.97e-6
    35.0  |      2.49e1   |     2.21e-3
    40.0  |      2.69e0   |     4.84e-3
    45.0  |      1.71e1   |      2.00e0
    50.0  |      1.17e1   |      1.55e1
    55.0  |      3.31e1   |      1.67e1
```

At t = 25 the f32 distance of 19.9 is the scale of the attractor, so the forecast
shares no information with the reference, while f64 still tracks Float106 to eight
decimal places. By t = 45 f64 has diverged too. The f32 distance at t = 45 (17.1) is
smaller than at t = 25, which is not recovery: past its horizon, the distance
between uncorrelated trajectories carries no information.

## Why precision sets the horizon

A chaotic system amplifies perturbations exponentially, at a rate set by the leading
Lyapunov exponent, here `λ ≈ 0.906`. Roundoff at machine epsilon is such a
perturbation. An error ε grows as `e^{λt}` until it reaches the scale of the
attractor, so the horizon scales as `ln(1/ε)/λ`:

```text
f32       (ε ≈ 1.2e-7)    t ≈ 17.6
f64       (ε ≈ 2.2e-16)   t ≈ 39.8
Float106  (ε ≈ 1.0e-32)   t ≈ 81.3
```

The measured horizons sit four to five time units above the law. The example README
attributes this to bursty local stretching. The two sets measure different
quantities and should not be mixed in one citation. Going from f32 to f64 adds nine
orders of magnitude of precision and roughly doubles the horizon.

## How the example is built

Most examples carry a one-line alias, `pub type FloatType = f64;`, and changing that
line re-runs them at another precision. This one needs three precisions at once, so
it instantiates the same function at each type: `model::run::<f32>`,
`model::run::<f64>` and `model::run::<Float106>`.

The run is a causal chain:

```rust
CausalFlow::effect()
    .next(simulate)
    .next(analyse)
    .run(...)
```

`PropagatingEffect` short-circuits if a trajectory goes non-finite, so a diverged
forecast stops the chain instead of feeding NaN into the analysis stage.
